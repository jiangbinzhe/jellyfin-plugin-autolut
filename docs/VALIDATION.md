# 本地验证记录

- Linux / .NET 10 Release 编译：0 警告，0 错误。
- 47 项程序检查通过，包括用户/媒体/设备白名单、命令图限制、LUT 校验和不可变会话文件、真实 FFmpeg 抽帧、Node 调色计算、无肤色回退，以及仅恢复运行时文件用户执行位。
- 独立 Jellyfin 12.1 的正式仓库安装后端测试通过：读取清单、MD5 校验、ZIP 解压、重启后插件 Active。
- 人为移除 Node 执行位后，自动分析流程可恢复执行位并生成 LUT。
- 实际 PlaybackInfo 测试：选定用户/媒体强制视频转码，不匹配设备仍可直放。
- 测试实例使用独立数据目录、仅监听回环地址，测试后已关闭。
- 源码和 ZIP 使用明确内容清单，并检查已知私有路径与凭据模式；未发现匹配。该检查不是完整安全认证。

尚未验证：最终插件在目标 NAS 上的 QSV/HLS 实播、长期性能、多用户并发、浏览器与服务端色彩管理逐像素一致性。

以上检查在本地整理阶段完成；首次公开发布在仓库所有者确认后进行。

- .NET 10 Release 编译无错误、无警告；完整本地检查 68 项通过（含真实 FFmpeg/Node 抽帧）。
  未配置真实 FFmpeg 时基础程序检查为 62 项，不应与完整检查混称。
- 隔离 Jellyfin 12.1 经正式插件仓库安装后端安装 0.1.2.0，确认清单校验、ZIP 解压、重启 Active，且加载 DLL 与安装包一致。再次移除 Node 执行位后，自动分析可恢复并运行。
- Android 2.7.3、Swiftfin 1.6.1 Swiftfin 模式、Native 模式的代表性请求，各验证普通播放、文本字幕和音轨切换。
- 加上强制直放、下载、烧录字幕和排除设备，共 13 个 HTTP 场景通过；9 个 LUT 实际生成并保留。
- 限额设为 1，正常播放结束后仍能继续创建后续会话；HLS 停止编码不会提前释放额度。

- fixtures 是源码派生的精简样本，不是设备抓包；没有运行 Android/iOS App。
- 尚未验收：手机 HLS 解码/字幕呈现、NAS QSV 像素输出与性能、真实 seek/音画同步，以及所有异常退出和音轨切换的会话回收。
