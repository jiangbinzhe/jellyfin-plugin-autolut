# 0.1.7 预发布版 — 隔行与 SMPTE 170M SDR

新增默认关闭的 **“兼容隔行／SMPTE 170M SDR 视频”**：

- 保留 Jellyfin 已有的 VAAPI 核显去隔行和帧率选择，继续使用 QSV 编码。
- 三项色彩标记均为 SMPTE 170M 的 8-bit SDR，先完整转换色域、传递函数与矩阵到 BT.709，再套 LUT；并非只改标记。
- 自动分析也先去隔行、转换色彩。每个会话冻结处理方案，原片与媒体库元数据不改写。
- 明确拒绝不支持的去隔行或色彩处理图，保留普通播放。按钮提示包含隔行兼容选项，便于定位限制。

## 更新与启用

固定插件仓库地址不变：

https://raw.githubusercontent.com/jiangbinzhe/jellyfin-plugin-autolut/main/manifest.json

安装 **0.1.7.0**，重启 Jellyfin，刷新网页或重开 App。进入 Auto LUT 设置，勾选 **兼容隔行／SMPTE 170M SDR 视频**，保存并重新播放。超过 1080p 的输入还需单独启用 4K UHD 选项；未标记色彩的隔行视频还需开启按 BT.709 解释的选项。

保持原有用户／媒体库范围；自动模式仍可能因没有可用肤色而跳过。实际应用日志应出现 `AutoLut applied`，含 `smpte170m-to-bt709` 和／或 `vaapi-deinterlace` 后缀，只有按钮“开”不证明滤镜已经应用。

## 验证与限制

本地 Release 编译零警告／零错误；214 项程序断言、9 项网页脚本测试、4 项清单测试通过。覆盖策略边界、实际命令结构、独立公式的像素参考、移动隔行画面的分析、输出逐行与 BT.709 标记、会话冻结和已有功能回归。

核显负责解码、去隔行、缩放、编码；本版的色彩转换与 LUT 仍使用 CPU，可能增加负载。完整 VAAPI→CPU→QSV 链路仍需目标 NAS 实播验收，本地 CPU 测试不代表已验证硬件像素或实时速度。建议先单路、无烧录字幕、1080p 输出测试，检查画面、音画同步、定位和至少 10 分钟稳定播放。

仍不支持 HDR／Dolby Vision／HDR10+／10-bit、混杂或不完整的 SMPTE 170M 标记、旋转、超过 3840×2160、复杂烧录字幕图。没有新增全 GPU LUT，也未修复 Swiftfin 默认播放器黑屏。
